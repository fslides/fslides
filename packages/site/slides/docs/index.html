Documentation

Everything you need to author, review, narrate, and publish decks that live in git.

Quickstart

$ npm install -g fslides
$ fslides scaffold my-deck   # GitHub repo + CI + Pages + comments, one command
$ cd my-deck && npm install
$ fslides serve              # author with live reload

scaffold needs the GitHub CLI authenticated (gh auth login). For a local-only deck without a repo, use fslides create my-deck.

Every push to main rebuilds and publishes your deck to GitHub Pages. That's the whole publishing story.

Writing slides

A slide is a plain HTML file in slides/, designed on a fixed 1280×720 canvas. Any CSS, any JS, any library. Add the file, then register it in fuckslides.config.js:

slides: [ 'cover.html', 'my-new-slide.html' ],
labels: [ 'Cover',      'The Big Idea' ],

Start from a designed template, or from scratch. The full slide skeleton and hard rules live in agents.md — written for AI agents, equally correct for humans. Which hints at the fastest authoring path: point Claude (or any agent) at your deck repo and describe the slide you want. HTML in, HTML out — there's a packaged skill: /plugin marketplace add fslides/fslides in Claude Code.

The player

fslides serve opens your deck in the player. Keyboard: ←→ navigate · G overview grid · T filmstrip · N notes · V play narration · M record · K comments · F present fullscreen.

Speaker notes live in notes.json and are editable in the Notes panel — they ship with the deck and feed the teleprompter.

Narration

Click Record in the toolbar: audio or camera per slide, with a pop-out teleprompter reading your notes at eye level, live waveform, device pickers, and virtual backgrounds (blur or custom image — baked into the recording).

  • Recordings land in slides/recordings/ — commit and push like any file (scaffolded decks track them with Git LFS so re-takes don't bloat clones)
  • Viewers hit Play on the published deck; camera takes render in a draggable bubble, and playback auto-continues across slides

Review & comments

Reviewers right-click any element on a slide — a headline, a chart, a block — and pin a comment thread to it. Drag-select to comment on a group. The Comments panel is a deck-wide inbox: click any thread to jump to its slide.

Underneath, threads are GitHub issues on your deck repo (one per slide) — permissioned, notifiable, readable forever without fslides. On published decks, commenting uses a one-popup GitHub sign-in; the fslides GitHub App (issues-only permission) is installed on the repos you choose during that popup.

Private repo? Comments work in fslides serve through your local gh auth with zero setup.

Command reference

CommandWhat it does
fslides serveLocal player: live reload, notes, narration recording, comments
fslides scaffold <name>New deck as a GitHub repo — files, CI, Pages, comments wired
fslides create <name>New local-only deck
fslides add-slide <name>Scaffold one slide file
fslides build [dir]Deployable static folder (what CI publishes)
fslides export [out.html]Single self-contained HTML file
fslides pdf / pptx / gifFormat exports

Contributing to a deck

$ git clone https://github.com/<owner>/<deck>.git && cd <deck>
$ npm install && npm run serve
  • Install git-lfs (brew install git-lfs) to fetch narration recordings
  • Edit slides like code; open a PR; CI publishes on merge
