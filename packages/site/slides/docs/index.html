Author, review, narrate, publish — decks that live in git. (fslides is short for f*ckslides — the name is provocative on purpose; so is the bat.)

Abuse or phishing on a hosted deck? Report it here or email security@fslides.dev.

Quickstart

$ curl -fsSL https://fslides.dev/install | sh   # or: npm install -g fslides
$ fslides scaffold my-deck   # repo + live URL + comments · charcoal template by default
$ cd my-deck && npm install
$ fslides serve              # author with live reload

scaffold needs the GitHub CLI authenticated (gh auth login). For a local-only deck without a repo, use fslides create my-deck.

Every push to main is live at you.fslides.dev/your-deck within a minute — rendered straight from the repo, no CI, no build step. That's the whole publishing story.

Writing slides

A slide is a plain HTML file in slides/, designed on a fixed 1280×720 canvas. Any CSS, any JS, any library. Add the file, then register it in fslides.config.js:

slides: [ 'cover.html', 'my-new-slide.html' ],
labels: [ 'Cover',      'The Big Idea' ],

Start from a designed template, or from scratch. The full slide skeleton and hard rules live in agents.md — written for AI agents, equally correct for humans. Which hints at the fastest authoring path: point Claude (or any agent) at your deck repo and describe the slide you want. HTML in, HTML out — there's a packaged skill: /plugin marketplace add fslides/fslides in Claude Code.

Content density

Let your audience choose how much they read. Add density: { default: 3 } to fslides.config.js and the player shows a density dial (1 to 5, keys - +). At 1 a slide is one visual or a quote, at 2 a title and the essentials, 3 is the slide as designed, and 4 to 5 reveal more context. The layout reorganizes itself as the level changes.

The level is saved per slide, in the slide itself (<html data-density="3">). Turn the dial while running fslides serve and the slide file is updated, so the choice travels with the deck: into builds, single-file exports, hosted decks and PDFs. Viewers can still adjust it for themselves.

<p data-d="4">shown at density 4 and above</p>
<p data-dmax="1">shown only at density 1</p>
html[data-density="1"] .visual { transform: scale(1.15); }   /* per-level layout */

Each slide exports at its saved level; fslides pdf --density 5 forces the full version everywhere. Details in agents.md.

Styles & skills

A style packages a deck's design system so the next deck looks the same: a design brief (SKILL.md), shared CSS/JS, and reference slides. Applying one installs the brief as a project skill, so your agent follows it for every slide it writes.

$ fslides style add <path | git-url[#subdir]>
$ fslides create my-deck --style <name>   # or apply: fslides style use <name>

Browse the skills catalog, or package your own: see agents.md for the format.

The player

fslides serve opens your deck in the player. Keyboard: ←→ navigate · G overview grid · T filmstrip · E edit this slide · N notes · V play narration · M record · K comments · F present fullscreen · W present in window.

Edits on disk live-reload the player. While the in-browser editor is open, that full-page refresh is skipped — the editor already updates its own preview on save. Disable live reload for a tab with ?noreload=1, or deck-wide with liveReload: false in fslides.config.js.

Speaker notes live in notes.json and are editable in the Notes panel — they ship with the deck and feed the teleprompter.

Narration

Click Record in the toolbar: audio or camera per slide, with a pop-out teleprompter reading your notes at eye level, live waveform, device pickers, and virtual backgrounds (blur or custom image — baked into the recording).

  • Recordings land in slides/recordings/ — commit and push like any file (scaffolded decks track them with Git LFS so re-takes don't bloat clones)
  • Viewers hit Play on the published deck; camera takes render in a draggable bubble, and playback auto-continues across slides

Review & comments

Reviewers right-click any element on a slide — a headline, a chart, a block — and pin a comment thread to it. Drag-select to comment on a group. The Comments panel is a deck-wide inbox: click any thread to jump to its slide.

Underneath, threads are GitHub issues on your deck repo (one per slide) — permissioned, notifiable, readable forever without fslides. On published decks, commenting uses a one-popup GitHub sign-in; the fslides GitHub App (issues-only permission) is installed on the repos you choose during that popup.

Private repo? Comments work in fslides serve through your local gh auth with zero setup.

Contributing to a deck

$ git clone https://github.com/<owner>/<deck>.git && cd <deck>
$ npm install && npm run serve
  • Install git-lfs (brew install git-lfs) to fetch narration recordings
  • Edit slides like code; open a PR; CI publishes on merge
