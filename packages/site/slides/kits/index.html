kits

A template gives you three slides. A kit gives your agent the whole design system: atmosphere, palette, type, layout, motion, and the rules a brand team would enforce. Install it once, and every slide written in the deck stays on-brand, by you or by Claude.

how it works
1. installA kit is a folder with a design brief (SKILL.md), shared CSS/JS, and reference slides. Install it from a path or a git repo.
2. start or applyCreate a deck from the kit's starter slides, or apply it to a deck you already have. Your slides are never overwritten by use.
3. your agent follows itThe brief is installed as a project skill in .claude/skills/. Claude Code picks it up automatically for every slide it writes in that deck.
$ fslides kit add <path | git-url[#subdir]>   # install into ~/.fslides/styles
$ fslides kit list                            # what you have
$ fslides create my-deck --style <name>        # new deck from the kit (scaffold --style works too)
$ fslides kit use <name>                     # apply to the deck you're in

elastic-web

Elastic teams

The Elastic 2026 web language: a white canvas, the flat Elastic palette, Inter with IBM Plex Mono callouts, isometric solids that assemble themselves, dot-matrix fields and big blue stats. It was extracted from the Elastic Observability deck.

  • Design brief: atmosphere, grid, type scale, palette roles
  • Isometric engine: solids, footprints, callouts, draw order
  • Motion rules that survive PDF export
  • Copy rules and component patterns
  • Starter slides: cover, platform, proof point, closing
  • The official Elastic platform graphic, rebuilt to spec
$ fslides kit add <elastic-style-repo>#collaterals/fslides-styles/elastic-web
$ fslides create my-deck --style elastic-web

This kit is distributed from an internal Elastic repository, so you need access to it to install.

make your own

Any deck with a look worth repeating can become a kit. Four pieces:

my-kit/
├── style.json   # { "name", "description", "starter": { "slides": [...], "labels": [...] } }
├── SKILL.md     # the brief: frontmatter name + description, then the rules
├── assets/      # shared CSS/JS → copied to <slidesDir>/style/
└── slides/      # starter + reference slides (link style/… for assets)

Write the brief the way you'd brief a designer: what the deck should feel like, the exact tokens, and the mistakes you've already seen. Full format in agents.md.
